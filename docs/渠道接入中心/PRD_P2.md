# EcomAgent 渠道接入中心 PRD（P2）

状态：P2 设计基线，需在取得商家授权后冻结，2026-07-21  
关联文档：[实现文档](实现文档_P2.md)、[架构文档](架构文档_P2.md)、[验收文档](验收文档_P2.md)

## 1. 产品定位

渠道接入中心是业务核心之外的独立连接系统。它处理淘宝、拼多多、抖音/抖店、小红书、ERP 等外部平台的授权、字段、同步、回调、限流和错误差异，并将结果转换为业务核心可理解的标准对象。

它不是第二套运营后台，不负责选品评分、商品文案、毛利计算、客服话术、人工审批、调价决策或投放决策；这些均属于业务核心。

## 2. 启用前提与范围

P2 开发和启用必须同时满足：

1. 存在愿意试用的真实商家，且取得合法、可撤销的店铺授权。
2. 确定目标平台、应用主体、所需权限和平台资质。
3. 明确可同步的数据范围、个人信息处理方式、Connector 验收数据和人工停用方案。
4. 业务核心的标准商品、订单、物流、售后模型已经通过 P1 CSV/Excel 数据验证。

首次 Connector 默认范围为：授权、商品/SKU、价格/库存、订单、物流、售后状态与可获得经营指标的**只读同步**。平台聊天自动收发、商品发布、推广投放、改价、退款、补发等写操作均不属于 P2 默认范围。

## 3. 用户与职责

| 用户 | 目标 | 权限 |
| --- | --- | --- |
| 管理员 | 发起授权、查看同步状态、启停 Connector、处理异常 | 仅管理员可操作渠道连接和受控执行审批 |
| 运营/内容 | 查看商品同步和数据新鲜度 | 只读状态摘要，不接触凭据 |
| 客服 | 查看订单/物流/售后事实与异常提示 | 只读与会话相关事实，不接触凭据和同步配置 |
| 渠道接入服务 | 同步、映射、投递、重试和告警 | 最小权限访问自身渠道凭据和队列 |

## 4. 功能需求

| 能力 | P2 最小要求 | 不做或后置 |
| --- | --- | --- |
| 连接授权 | 发起、回调、授权状态、过期提醒、撤销和重新授权 | 将 Token 暴露给业务核心或前端 |
| 数据同步 | 逐 Connector 拉取或接收商品、SKU、价格/库存、订单、物流、售后与获批经营指标；记录游标与新鲜度 | 未验证的全量历史迁移 |
| 数据映射 | 平台字段转换为标准对象，记录映射版本和来源摘要 | 将平台专有字段写入业务核心通用模型 |
| 事件处理 | 回调验签、去重、顺序控制、失败重放 | 未验签的公开回调入口 |
| 可靠性 | 单 Connector 队列、限流、超时、幂等、重试、死信和告警 | 多平台共用失败状态或无限重试 |
| 受控执行 | 接收带审批记录的请求并返回执行结果 | 默认开放任何写操作 |

## 5. 业务规则

- 一个 Connector 仅服务一个平台或一个 ERP 类型；新增平台通过新增 Connector 实现。
- 任一 Connector 的授权失效、限流、接口变更或任务失败，只暂停该 Connector，不影响业务核心和其他 Connector。
- 映射缺字段、状态无法对应或响应不可信时，返回“待人工处理”，不得猜测或伪造标准事实。
- 渠道原始载荷、Token、签名和限流状态不进入业务核心。
- 首个 Connector 平台由首家合法授权商家的实际经营平台决定；在此之前不锁定开发优先级。

## 6. 阶段目标

| 阶段 | 输出 |
| --- | --- |
| P0 | 标准契约、服务边界和 Mock，不接平台 |
| P1 | CSV/Excel 映射验证标准模型；准备授权与数据最小化清单 |
| P2 | 一个首选 Connector 的只读同步、监控、告警、人工重放与单独验收 |
| P3 | 按单渠道、单动作、单独审批开放草稿发布、素材推送或受控调价等低风险写操作；不承诺排名 |
