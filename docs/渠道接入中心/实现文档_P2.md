# 渠道接入中心实现文档（P2）

状态：P2 开发交接依据，2026-07-21  
前提：满足 [P2 PRD](PRD_P2.md) 的商家授权与资质门槛。本文不表示当前已开始开发。

## 1. 服务模块

| 模块 | 职责 |
| --- | --- |
| Connection Manager | 管理授权流程、加密凭据、过期状态、撤销和重新授权 |
| Connector Runtime | 封装单一平台 API、字段映射、能力声明与错误转换 |
| Sync Orchestrator | 创建同步任务、维护游标、分批拉取、幂等和数据新鲜度 |
| Webhook Gateway | 回调验签、去重、顺序控制、投递和失败隔离 |
| Execution Gate | 校验业务核心审批、动作范围和幂等键，默认拒绝未启用写操作 |
| Queue & Retry | 每 Connector 独立队列、退避重试、死信、人工重放和停用 |
| Observability | 健康检查、限流、失败率、延迟、授权到期和告警 |

## 2. Connector 生命周期

```text
管理员发起授权
-> Connection Manager 保存加密凭据与授权范围
-> 管理员启用 Connector
-> 创建只读同步任务或接收验签回调
-> 映射为标准对象并投递业务核心
-> 记录游标、新鲜度、结果和审计
-> 失败：限流/重试/死信/告警
-> 管理员暂停、撤销或重新授权
```

## 3. 开发顺序

1. 实现版本化标准契约和 Mock Connector；由 CSV/Excel 数据验证对象完整性。
2. 实现连接状态机、加密凭据存储、独立数据库账号和管理员授权界面。
3. 实现首个 Connector 的商品/SKU、价格/库存只读同步，再扩展订单、物流、售后状态和获批经营指标。
4. 加入 Webhook、增量游标、幂等、限流、重试、死信、告警和人工重放。
5. 完成单 Connector 验收后，才评估第二个平台；不得复制粘贴平台逻辑到业务核心。

## 4. 标准输入输出

| 方向 | 最小字段 |
| --- | --- |
| 业务核心 -> 接入中心 | 连接 ID、请求类型、标准对象 ID、审批记录 ID、操作范围、幂等键 |
| 接入中心 -> 业务核心 | 渠道、外部对象 ID、标准对象版本、来源更新时间、同步时间、映射版本、新鲜度、价格/库存或经营事实、结果/错误摘要 |
| 接入中心内部 | Connector ID、任务 ID、游标、重试次数、限流状态、死信原因、审计关联 ID |

## 5. 实现约束

- 业务核心和接入中心使用不同数据库账号；接入中心原始载荷和凭据不可被业务核心直接查询。
- 同步工作必须异步执行，不阻塞业务核心的用户请求。
- 每个 Connector 配置独立的超时、限流、队列、重试次数和熔断开关。
- 任何写请求必须含有效审批记录、明确动作范围和幂等键；P2 默认关闭。P3 的调价请求还必须携带最低毛利、价格上下限、最大幅度、最大频率、库存阈值和停用开关版本。
- 平台规则、资质或 API 变化时，先停用受影响 Connector，再更新映射和验收用例。
