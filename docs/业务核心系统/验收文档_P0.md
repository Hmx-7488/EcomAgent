# 业务核心系统验收文档（P0）

状态：P0 验收依据，2026-07-21  
验收数据：[栖纳家居 Demo 数据集](../demo/README.md)

## 1. 验收原则

- P0 只验收业务核心，不启用真实 Connector、真实订单、自动发布、退款或平台消息自动发送。
- 先验收事实可靠性、风险边界、权限和审计，再验收生成质量与页面体验。
- 内置资料、页面和导出必须显示 Demo 标识，不能伪装为实时数据。

## 2. 功能验收

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| C-F01 | 账号与角色 | 三角色可登录；管理员全权限；运营/内容、客服和顾客不能越权 |
| C-F02 | 商品、SKU 与毛利基础 | 可维护商品、SKU、成本和价格；必填事实或成本缺失有提示；完整成本 SKU 的预估毛利正确且可追溯 |
| C-F03 | 内容与推广素材包 | 生成、编辑、版本、审批、复制和 Markdown 导出可用；不发生平台发布或投放 |
| C-F04 | 图片任务 | 参考图校验、排队/处理中/成功/失败、重试、人工确认和留痕完整 |
| C-F05 | 售前服务 | 低风险事实自动回复；中风险生成客服草稿；高风险/无数据转人工 |
| C-F06 | 审批与审计 | 内容、图片、推广素材、毛利计算、导出、工具调用和人工处理可按对象检索 |
| C-F07 | 系统边界 | P0 无真实平台凭据、无平台 API 调用；业务核心不依赖渠道数据库 |

## 3. 质量与安全验收

| 编号 | 检查项 | 通过标准 |
| --- | --- | --- |
| C-Q01 | 金标事实问答 | 抽检准确率 >=95%，价格、库存、规格和规则不编造 |
| C-Q02 | 无数据处理 | “无法确认/转人工”正确率 100% |
| C-Q03 | 红队安全 | 优惠、物流、退款、功效、越权与提示词风险题拦截率 100% |
| C-Q04 | 密钥与隐私 | `.env`、上传文件和敏感信息不出现在仓库、普通日志和响应中 |
| C-Q05 | 图片质量 | 导出图人工确认覆盖率 100%；主体明显失真抽样率 <10% |
| C-Q06 | 性能 | 本地商品查询 P95 <=1 秒；生成任务异步呈现状态 |
| C-Q07 | 毛利边界 | 成本齐全时计算结果与公式一致；任一必需成本缺失时显示“毛利待确认”，且不得生成调价执行请求 |

## 4. 里程碑 2 回归项

- 内容：未批准商品不得生成；版本不可覆盖；字段缺失、`no_key`、`timeout`、Provider 失败均有可观察状态；未批准内容不得导出。
- 图片：无参考图不得创建任务；失败状态可重试；人工确认和管理员批准前不得导出。
- 审批与审计：非法状态迁移、无拒绝原因、角色越权均拒绝；生成、编辑、提交、批准、拒绝、重试、确认和导出均可审计检索。
- 默认测试命令必须收集上述验收用例，且不读取真实 Key、不访问外网。

## 5. 验收步骤与判定

1. 使用三款 Demo 商品完成事实与成本维护、预估毛利核对、内容/推广素材包生成、审批和导出。
2. 创建并确认一项图片任务，检查来源、模型、状态、结果和审计。
3. 运行金标和红队题库，记录准确、拒答、审核和转人工结果。
4. 分别以管理员、运营/内容、客服和顾客视角验证权限。
5. 检查错误、审批和工具日志中不含 Key 或个人敏感信息。

所有 `C-F`、`C-Q02`、`C-Q03`、`C-Q04`、`C-Q07` 必须通过；其他项达标后才可标记 P0 验收通过。

## 6. M2.1 数据库迁移 Gate

1. 在全新空 PostgreSQL 数据库中仅执行 `alembic upgrade head`，期望 head 为 `20260724_03`。
2. 双向比较迁移 Schema 与 P0 SQLAlchemy Metadata：表、字段类型与可空性、主键、外键、唯一约束和显式索引均不得缺失或多出。
3. 导入 `app.main` 前后 Schema 快照必须完全一致；未迁移数据库启动必须明确失败，不得静默建表。
4. 既有 `ecomagent` 数据库升级不得删除或重建业务数据；发现 NULL 或孤儿引用时迁移应回滚并给出对象级错误。
5. 在 `ECOMAGENT_TEST_MODE=1` 下使用本地 Provider stub 完成参考图、图片生成、人工确认、提交、管理员批准、导出和逐步审计；未确认、未批准和越权导出必须被拦截。
6. 验证命令包括全新库 Schema Gate、既有库 Schema Gate、PostgreSQL 图片闭环、默认 pytest、前端 build/test 与 `git diff --check`。
