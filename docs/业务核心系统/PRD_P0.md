# EcomAgent 业务核心系统 PRD（P0）

状态：正式开发与维护依据，2026-08-12
关联文档：[实现文档](实现文档_P0.md)、[架构文档](架构文档_P0.md)、[验收文档](验收文档_P0.md)、[后续阶段路线图](../后续阶段路线图.md)

## 1. 产品定位

业务核心系统是面向单个中小电商商家的 AI 经营工作台。P0 以居家收纳用品为首批类目，使用虚构品牌“栖纳家居”的 Demo 数据，完成从商品/SKU 与成本事实，到预估毛利、内容与推广素材、售前问答和审批留痕的闭环。

P0 不是全流程自动经营系统，不接真实平台 API、真实订单或自动写操作。订单、物流、售后和经营分析仅保留标准模型边界，后续按阶段启用。

## 2. 用户、角色与目标

| 用户 | 目标 | 权限边界 |
| --- | --- | --- |
| 管理员 | 配置系统并对最终输出负责 | 全权限；管理账号、一级商品类目、模型、规则、白名单、审批、审计和未来渠道授权 |
| 运营/内容 | 维护商品事实，生成并完善内容和素材 | 创建、编辑商品与 SKU、选择已有一级类目、维护成本并提交审批；不能新增类目、改系统配置或绕过审批 |
| 客服 | 处理顾客问题和待审核回复 | 使用已授权事实、审核中风险草稿、转人工；对商品、SKU、类目和成本保持只读，不能编辑商品事实或模型规则 |
| 顾客 | 获取售前信息 | 仅访问独立咨询页；无后台与配置访问权 |

P0 成功定义：测试者可在 30 分钟内完成一款 Demo 商品的内容包和场景图审批导出；低风险事实问答可自动回复，中高风险问题均不越权处理。

## 3. P0 范围

| 能力 | P0 必须交付 | P0 明确不做 |
| --- | --- | --- |
| 本地账号与角色 | 三固定角色登录、后端权限校验、管理员全权限 | 多租户、成员邀请、SSO、自定义角色 |
| 商品与利润基础 | 商品、一级类目字典、SKU、规格、材质、容量、颜色、包装、成本字段、价格、预估毛利和来源维护；商品、SKU、成本独立保存 | 真实平台商品同步、自动库存更新、实际财务记账、自动调价 |
| 内容与推广素材包 | 标题、卖点、详情、参数、FAQ、售前话术、主图/场景图候选；版本、审批、复制/Markdown 导出 | 自动发布、平台投放、活动优惠、自动购买流量 |
| 商品图片 | 参考图、场景模板、异步生成、状态、人工选择和导出留痕 | 自动抠图、批量 SKU、平台裁切和自动发布 |
| 顾客售前服务 | 独立本地咨询页、事实检索、风险分级、自动答复/审核/转人工 | 价格库存承诺、售后裁决、平台站内信自动收发 |
| 审批与审计 | 内容、图片、导出、回复和工具调用留痕 | 替代人工承担经营或售后责任 |

## 4. 关键业务流程

```text
商品事实录入并独立保存
-> 选择已有一级类目（管理员可另行新增类目）
-> SKU/规格独立新增或保存
-> SKU 字段与脏状态校验
-> 成本独立保存；存在未保存 SKU 价格时阻止提交
-> 成本完整性校验与预估毛利计算
-> 生成内容包或场景图片
-> 运营编辑并提交
-> 管理员审批
-> 复制或 Markdown 导出

顾客提问
-> 意图识别与风险判断
-> 查询商品/SKU/已审批 FAQ/规则
-> 低风险且事实完整：自动回复
-> 中风险：客服审核草稿后发送
-> 高风险、无事实、投诉或要求人工：转人工
-> 保存来源、风险、处理方式和审计记录
```

## 5. 风险与审批规则

自动回复白名单仅限已审批且无歧义的材质、尺寸、容量、颜色、包装、安装/使用方式和适用场景。

价格、库存、优惠、具体发货或到货承诺、退款、补发、换货、质量争议、认证、功效、投诉和未录入信息不得自动回复。系统必须创建审核草稿、转人工或说明无法确认。商品内容、图片、推广素材、毛利规则、导出以及所有未来写操作必须人工确认。

## 6. 数据与非功能要求

- 所有页面、导出与日志中的内置资料明确标记“Demo 数据”。
- 商品事实、成本、价格、毛利结果、内容版本、素材任务、审批、工具调用和会话处理均可追溯。
- P0 预估毛利率 = `(实收售价 - 采购成本 - 包装成本 - 运费补贴 - 平台扣点 - 推广分摊 - 售后损耗) / 实收售价`；任一必需成本缺失时必须显示“毛利待确认”，不得给出可用于调价的结论。
- SKU 零售价允许为 `0`，创建和更新使用相同规则；零售价为 `0` 时即使成本已保存，
  毛利仍保持 `pending_confirmation`，不得除以零或生成可执行调价结论。
- P0 顾客页面为本地演示入口；公网访问属于 P1 部署事项。
- 文本和图片调用统一通过 DashScope Provider 适配层；密钥仅从部署环境变量读取。
- 后台以电脑端为主；顾客页兼容手机浏览器。

## 7. 商品管理维护规则（2026-08-12）

- 一级商品类目使用受控字典；管理员可新增类目，运营/内容只能选择已有类目，客服只读。
- 商品保存请求不得携带 `skus`；已有 SKU 独立保存，新规格通过独立 SKU 创建动作新增。
- 前端必须显式展示 SKU 脏状态并使用并发保存锁，避免重复请求或覆盖在途保存。
- 存在未保存 SKU 价格时必须阻止成本保存；零价 SKU 保存成本后明确提示毛利仍待确认。
- 商品、SKU、成本保存均提供中文成功/失败反馈；业务校验失败使用安全中文 `422`
  响应，不暴露内部异常、数据库结构或调用栈。
- 上述维护以 Revision `20260811_05` 和代码发布基线
  `65470f765e39f3d0bce8dd69f680330343293186` 为正式实现事实。

## 9. 后续边界

选品评分、实际利润分析、推广效果复盘、运营看板和调价建议属于 P1；真实平台同步属于 P2；平台发布、推广推送和受控调价属于 P3。详细范围以[后续阶段路线图](../后续阶段路线图.md)为准。业务核心不因平台差异复制商品、客服或审批逻辑。
