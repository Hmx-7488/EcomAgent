# 业务核心系统实现文档（P0）

状态：P0 最终实现与部署依据，2026-07-28
前提：遵守 [P0 PRD](PRD_P0.md) 与 [架构文档](架构文档_P0.md)。本文件定义实现范围，不表示已完成正式开发。

## 1. 实现原则

- 先实现事实、权限、审批和审计，再实现生成能力和页面体验。
- API 路由只做参数校验、身份上下文和响应；领域服务负责业务规则。
- 所有生成必须有无 Key、字段缺失、Provider 失败和超时四种可测试状态。
- P0 不接平台 SDK 或真实平台 API；通过 Mock 和标准契约验证未来边界。

## 2. 模块与交付顺序

| 顺序 | 模块 | 关键交付 |
| --- | --- | --- |
| 1 | 身份与权限 | 本地账号、密码哈希、固定角色、后端授权守卫、管理员全权限 |
| 2 | 商品与利润基础 | 商品/SKU CRUD、成本字段、预估毛利、完整性、规则版本、Demo 标识 |
| 3 | 内容与推广素材中心 | 内容包、图文素材包、版本、字段来源、审批状态、复制和 Markdown 导出 |
| 4 | 素材中心 | 文件校验、场景图任务、Provider 状态、确认与导出记录 |
| 5 | 受控售前服务 | 风险判断、只读工具、自动回复白名单、审核队列、转人工 |
| 6 | 审计与验收 | 审批、工具调用、错误日志、金标/红队回归、权限测试 |

## 3. 最小领域接口

| 领域 | 必需动作 | 约束 |
| --- | --- | --- |
| 商品与 SKU | 创建、编辑、查询、完整性检查、成本维护、预估毛利计算 | 强事实与成本字段可追溯，不能由模型覆盖；缺成本不产生可执行结论 |
| 内容与推广素材包 | 创建草稿、生成、编辑、提交、审批、导出 | 导出必须存在审批记录；仅生成素材，不向平台投放 |
| 图片任务 | 创建、查询状态、重试、确认、导出 | 异步执行；失败不伪装为成功 |
| 售前会话 | 提问、检索事实、生成结果、审核、转人工 | 所有结果保存风险等级和来源摘要 |
| 管理配置 | 管理用户、规则、白名单、Provider 配置 | 仅管理员可写 |
| 审计 | 查询对象、动作、操作者、前后状态和时间 | 不记录 API Key 或不必要个人信息 |

## 5. 与渠道接入中心的预留

P0 仅定义标准对象和接口边界：商品、SKU、成本、价格规则、推广素材、订单、物流、售后、会话事件、同步结果与执行结果。业务核心不得读取渠道数据库，不得保存渠道 Token，不得绕过渠道接入中心直接调用平台 API。P0 不创建调价或投放执行请求。

## 6. 里程碑 2 API 与状态机（冻结）

- 内容包：`GET/POST /api/content/packages`、`GET/PATCH /api/content/packages/{id}`，以及 `generate`、`submit`、`approve`、`reject`、`export` 动作。内容仅可基于 `status=approved` 的商品事实创建；类型为标题、卖点、详情、参数、FAQ、售前话术和图文推广素材。每次编辑或生成追加内容版本，已批准版本不可覆盖。
- 内容审批状态机：`draft -> submitted -> approved|rejected`；拒绝必须带原因。运营/内容创建、编辑、生成、提交；管理员批准、拒绝、导出和查询审计。仅已批准内容可 Markdown 导出。
- 图片：`POST /api/images/reference` 上传并校验参考图；`GET/POST /api/images/tasks` 与单任务 `retry`、`confirm`、`submit`、`approve`、`reject`、`export` 动作。任务状态为 `pending|processing|completed|no_key|timeout|failed|field_missing`，审批状态独立为 `draft|submitted|approved|rejected`。
- 图片导出前提：任务完成、人工确认并经管理员批准。重试仅允许 `no_key`、`timeout`、`failed` 或 `field_missing`。不得实现平台裁切、发布、批量 SKU 生图或平台上传。
- 所有生成、编辑、提交、批准、拒绝、重试、确认和导出写入 `audit_events`；记录来源摘要、事实版本、Provider、模型名和安全错误摘要，绝不记录 Key。客服与匿名顾客不得访问上述资源；统一错误响应和 `/api` 前缀保持不变。

## 7. 开发完成定义

每个模块应同时具备接口测试、权限测试、失败状态、审计记录和对应验收用例。仅页面可操作、没有来源、审批或错误状态，不得标记为完成。

## 9. 里程碑 3 API、状态机与数据契约（冻结）

### 9.1 匿名顾客 API

- `GET /api/customer/products`：仅返回可咨询的 `approved` 商品名称和安全摘要，不返回价格、库存、成本、毛利或内部字段。
- `POST /api/customer/conversations`：以 `product_id` 创建匿名会话，返回 `id`、一次性明文 `access_token`、`status` 和时间。令牌必须由安全随机数生成，服务端只保存不可逆摘要；不得写入日志、审计或后续普通响应。
- `GET /api/customer/conversations/{conversation_id}`：必须携带 `X-Conversation-Token`，仅返回该会话顾客可见消息、状态和安全提示。
- `POST /api/customer/conversations/{conversation_id}/messages`：必须携带 `X-Conversation-Token`，输入先 trim，纯空白统一返回 422。`open` 会话提交问题后执行风险与事实流程；`waiting_review` 或 `transferred` 会话只追加业务消息并维持原状态，不调用 Provider、不生成回复、草稿或重复通知；`resolved` 返回 409。不得允许仅凭会话 ID 读取或写入。

### 9.2 客服工作台 API

- `GET /api/service/conversations?status=waiting_review|transferred`、`GET /api/service/conversations/{id}`：仅 `customer_service` 和 `admin` 可访问，返回时间线、风险原因、事实来源摘要和内部待审核草稿，不返回成本、毛利、内部库存或访问令牌摘要。
- `POST /api/service/conversations/{id}/send`：仅允许对 `waiting_review` 会话发送人工审核后的回复；发送成功是 `waiting_review -> open` 的唯一触发动作。业务消息表保存原始草稿和最终内容，审计只保存消息 ID、是否编辑、长度或 SHA-256 摘要、操作者和时间。
- `POST /api/service/conversations/{id}/transfer`：客服或管理员手工转人工，必须提供原因；状态变为 `transferred`。
- `POST /api/service/conversations/{id}/resolve`：客服或管理员将会话标记为 `resolved`；它是 `transferred -> resolved` 的唯一触发动作。已解决会话不得继续发送顾客消息或客服回复。
- `operator_content` 对所有 `/api/service` 会话接口返回 `403`。

### 9.3 风险与状态机

- 会话状态：`open` 的中风险判断触发 `waiting_review`，高风险或 Provider 安全降级触发 `transferred`，客服审核发送成功触发 `waiting_review -> open`，客服或管理员解决操作触发 `transferred -> resolved`。客服也可把 `open|waiting_review` 手工转为 `transferred`。顾客在 `waiting_review|transferred` 的补充消息只追加到时间线，不触发状态迁移；`resolved` 顾客消息返回 409。
- 风险级别固定为 `low|medium|high`；决策固定为 `auto_reply|review_draft|transfer`。
- 确定性风险规则和事实完整性检查必须在 Provider 调用之前执行。低风险自动回复仅限材质、尺寸、容量、颜色、包装清单、安装/使用方式和适用场景，并且商品已批准、字段单值完整、来源可追溯；回答直接使用确定性事实模板，不调用模型。
- 价格、库存、优惠活动、具体发货/到货承诺、退款/补发/换货/改地址/售后裁决、质量争议/投诉、认证/功效/绝对化宣传、未录入/过期/冲突数据、明确要求人工和提示词攻击不得自动回复。
- 中风险使用 DashScope/Qwen 生成内部草稿并进入 `waiting_review`，草稿不出现在顾客可见消息中。模型请求只包含顾客问题与白名单安全事实摘要；Provider 适配器不持有数据库连接，Prompt 不包含成本、毛利、内部库存、Key 或会话令牌。高风险直接进入 `transferred`，顾客端固定显示“已转人工，请等待客服处理”，不得承诺响应时间。
- Qwen 未配置 Key 或发生 `timeout|failed|field_missing` 时一律安全降级为 `transfer`，不得把模型输出作为事实。测试通过依赖注入或 mock DashScope 覆盖全部状态，禁止访问真实 Provider。

### 9.4 数据与审计

- `conversations` 保存商品、令牌摘要、状态、最近风险与转人工原因；`conversation_messages` 追加保存顾客消息、自动回复、内部草稿、客服回复和状态消息；`conversation_decisions` 保存风险、决策、原因、Provider 状态及来源摘要；`conversation_fact_sources` 逐字段保存来源对象类型、ID、版本、字段摘要和数据时间。
- 模型只接收白名单工具返回的字段摘要，不持有数据库连接，不生成或执行自由 SQL。事实工具只读 `approved` 商品、有效 SKU 规格、已审批 FAQ 和规则。
- 审计动作至少包括 `conversation.created`、`message.received`、`risk.assessed`、`fact.queried`、`reply.auto_sent`、`draft.generated`、`draft.edited`、`reply.agent_sent`、`conversation.transferred`、`conversation.status_changed` 和 `provider.degraded`。顾客消息、草稿、客服回复和人工备注原文只保存在对应业务对象中；审计仅保存固定 reason code、对象/消息 ID、长度或 SHA-256 摘要及状态变化，不得包含 Key、令牌原文、令牌摘要或不必要个人信息。
- 里程碑 3 使用独立后继迁移 `20260726_04_m3_customer_service.py`，`down_revision=20260724_03`；不得修改已提交的 01、02、03。全新库、既有库、Metadata 对比及 `app.main` 导入无副作用继续作为迁移 Gate。

## 10. M4 集成与部署实现

### 10.1 认证与前端运行模式

- 认证契约统一为 `POST /api/auth/login` 和 `GET /api/auth/me`，Bearer Token 与固定角色 `admin|operator_content|customer_service` 的字段保持兼容。旧 `/auth/*` 不作为正式接口保留。
- 开发环境可显式开启 Mock；生产构建和 Docker 镜像必须注入 `VITE_USE_MOCK=false`。路由守卫先恢复当前用户，再按角色阻止越权页面；权限最终仍由后端逐接口校验。
- 集成测试覆盖真实 FastAPI 登录、错误凭据、未认证访问、角色路由和越权响应，不依赖 Nginx 特殊改写。

### 10.2 容器与迁移

- `postgres` 使用 PostgreSQL 16 和持久卷；`backend` 镜像安装声明依赖，以非特权进程运行，入口先执行 `alembic upgrade head` 再启动 Uvicorn；`frontend` 以 `VITE_USE_MOCK=false` 构建静态文件，并由 Nginx 同源代理 `/api` 与 `/uploads`。
- `.dockerignore` 必须排除 `.env`、虚拟环境、SQLite、uploads、缓存、`node_modules`、`dist`、测试报告和本地工具目录。Compose 不包含 Redis，因为 P0 运行代码未使用它。
- 全新卷从空库升级到 `20260726_04`；既有 `ecomagent` 库原地执行同一迁移链。两者都运行 Metadata Schema 双向对比，并验证导入 `app.main` 前后 Schema 不变。

### 10.3 Demo、Provider 与验收

- `python scripts/init_demo.py` 是幂等初始化命令；三个后台角色密码必须从 `DEMO_ADMIN_PASSWORD`、`DEMO_OPERATOR_PASSWORD`、`DEMO_SERVICE_PASSWORD` 注入，生产代码不内置弱密码。
- Docker 完整闭环脚本在 `ECOMAGENT_TEST_MODE=1` 下使用进程内 Provider stub，数据库仍连接 Docker PostgreSQL；stub 不暴露为生产 HTTP 路由。自动测试清空 Key 并阻断外网。
- 真实 Qwen 文本和图片 Smoke Test 不是自动验收前提。若执行，必须先报告调用次数并获得明确批准，且只记录安全状态和错误类别，不读取、打印或记录 Key。
- 本地商品查询性能必须记录环境、样本数和 P95；固定 Demo 金标与红队结果只代表封闭数据集回归，不代表真实线上泛化效果。`C-Q05` 图片主体质量保留为人工验收。
## 11. M4.1 图片完整性与隔离验收

- 参考图、图片 Provider 原始字节和 Google Base64 结果统一调用 `validate_image_bytes`。校验包含非空、最大文件大小、支持格式、宽高、最大像素数、Pillow decode/`verify()`/重新 `load()`，以及文件扩展名与实际格式一致；`Content-Type` 仅为辅助元数据。
- Qwen HTTPS 临时 URL 使用有限连接/读取超时、响应大小和重定向次数下载。下载内容验证后以 UUID 不透明本地文件名原子保存，临时 URL 不得直接写入 `Asset.storage_path`。
- 校验、写文件或数据库提交任一步失败时回滚事务并删除临时/最终文件；失败任务不得产生可审批 `Asset`。SQLite pytest fixture 只在测试目录显式创建上传目录。
- Docker 验收由 `run_isolated_p0_acceptance.py` 创建随机 PostgreSQL 数据库，执行 Alembic 全迁移和 P0 闭环，并在 `finally` 中删除验证库与本次新增上传文件。正式 Demo 库不承载自动验收数据。
- 前端镜像必须使用 lockfile 和 `npm ci`；PostgreSQL 宿主端口只绑定 `127.0.0.1`。`C-Q05` 样本目录不得放入离线占位图，真实图片调用与费用必须先获单独批准。
## 12. M4.2 Qwen 官方同步契约

- 图片模型由 `IMAGE_GEN_MODEL` 配置，P0 默认 `qwen-image-2.0`；`IMAGE_GEN_OUTPUT_COUNT` 固定为 `3`。创建任务时将实际模型 ID 快照写入 `ImageGenerationTask.model_name`，请求使用该任务快照。
- 中国大陆 P0 启动配置只接受 `IMAGE_GEN_MODEL=qwen-image-2.0`。非空 `IMAGE_GEN_API_BASE` 必须为 `https://<Workspace ID>.cn-beijing.maas.aliyuncs.com/api/v1` 格式的华北 2 Workspace 专属地址；旧公共 DashScope 图片地址、HTTP、其他地域或错误模型均在 Settings 初始化时明确失败。API Key、Workspace ID 与地域必须来自同一 Workspace。空 Key/空基址仍保留可观察的 `no_key` 安全降级。
- Qwen 图片编辑调用 `POST {IMAGE_GEN_API_BASE}/services/aigc/multimodal-generation/generation`。`input.messages` 恰好一条 `role=user` 消息，`content` 恰好包含经统一 Pillow 校验后的参考图 Base64 data URL 和一条编辑指令。参数固定包含 `n=3`、`size=1024*1024`、`watermark=false`。
- 同步响应只解析 `output.choices[0].message.content[*].image`。空 choices、缺失图片或少于三张均为 `field_missing`；请求/下载超时为 `timeout`；HTTP、URL、下载与图片校验失败为 `failed`。
- 三张结果必须全部下载并通过 HTTPS、大小、重定向与 Pillow 校验后才进入原子保存。任何一张校验或写入失败都会回滚数据库并删除本批次已写文件，任务不得标记 `completed`。
- API Key、参考图字节和 Base64 data URL 只存在于请求内存，不进入任务、审计、普通日志或错误摘要。自动测试精确 mock HTTP 请求和官方响应结构，并由全局外网阻断保证不会调用真实 Provider。
