## 阶段门槛

| 阶段 | 未满足即不得进入下一阶段的条件 |
| --- | --- |
| P0 开发 | P0 文档包、原型、Demo 数据、成本/毛利口径和验收口径完成；不接真实平台 API |
| P1 经营辅助 | P0 验收通过；CSV/Excel 模板、数据来源、选品评分口径、成本完整性和人工运营流程确认 |
| P2 接入 | 合法授权商家、目标平台、应用主体/资质、数据范围、Connector 验收方案与故障停用方案确认 |
| P3 受控执行 | 每项写操作的审批人、平台权限、最低毛利、幂等/回滚、频率限制、人工兜底和审计要求全部确认 |

## 变更规则

1. 修改 P0 业务核心能力时，先更新业务核心 PRD，再同步实现、架构和验收文档。
2. 修改平台接入、标准契约或 Connector 边界时，先更新渠道接入中心 PRD，再同步实现、架构和验收文档。
3. 后续阶段先更新路线图；获准启动后新建该阶段的 PRD、实现、架构和验收文档，不在 P0 文档中补写详细需求。
4. 跨系统契约变更必须同时更新两个系统的架构文档，并记录本台账的编号、原因和生效版本。
5. Obsidian 仅同步结论、状态和链接，不复制正式文档正文。
