# EcomAgent 项目总规划

关联文档：[文档入口](README.md)、[业务大框架](业务大框架.md)、[后续阶段路线图](后续阶段路线图.md)、[需求决策台账](需求决策台账.md)。

## 当前目标与边界

P0 交付“本地账号登录 -> 商品与 SKU/成本事实 -> 内容与推广素材包 -> 人工确认 -> 复制或 Markdown 导出 -> 顾客售前问答 -> 审计留痕”的可演示闭环。首批只覆盖栖纳家居的居家收纳 Demo 数据；不接真实平台，不做选品结论、运营看板、自动推广或自动调价。

P0 的成本与毛利只用于商品录入时的预估经营判断，不应被误解为真实财务核算或自动定价。

| 角色 | 主要责任 | 交付物 |
| --- | --- | --- |
| 产品负责人 | 范围、成本口径、规则、验收裁决 | PRD、字段字典、验收结论 |
| 交互/视觉 | 页面流程、空状态、风险状态、审批体验 | 原型、页面标注 |
| 后端开发 | 领域模型、API、Provider、规则、审计与任务状态 | 数据迁移、OpenAPI、测试 |
| 前端开发 | 商品、毛利、内容素材、问答、日志工作台 | 页面与组件测试 |
| 测试/产品 | 金标问答、红队、毛利边界与回归验证 | 测试报告、缺陷清单 |

## 工作分解与顺序

| 阶段 | 交付目标 | 完成标志 |
| --- | --- | --- |
| 0. 规划与环境 | 范围冻结、原型、架构、验收标准、Demo 数据、运行环境 | P0 文档包和开发前检查完成 |
| 1. 账号与经营事实 | 本地账号、角色、商品、SKU、成本字段、毛利规则 | 角色权限、商品 CRUD、成本校验与预估毛利可用 |
| 2. 内容与推广素材 | 内容包、图片候选、推广素材包、版本、审批、导出 | 基于已审批事实生成并导出图文素材 |
| 3. 顾客售前 Agent | 顾客咨询页、风险分级、审核与转人工、日志 | 金标、红队和角色权限通过门槛 |
| 4. 集成验收 | Demo 经营闭环、回归与体验验收 | 通过业务核心系统 P0 验收文档 |

## 后续阶段治理

P1-P3 的功能清单、边界、数据前提和启用门槛统一记录在 [后续阶段路线图](后续阶段路线图.md)。路线图不是开发依据：每个阶段启动前必须新增该阶段的正式 PRD、实现文档、架构文档和验收文档，再进入开发。

## 必须先设计、不得后补的事项

- 商品、SKU、成本、价格和毛利必须有统一字段口径、来源与生效时间。
- 内容资产具备版本、来源商品版本、审批状态、导出状态和操作人。
- 图片任务具备 Provider、模型名、来源图片、幂等键、状态、错误和人工确认。
- 强事实只能来自结构化查询；模型无法确认时必须拒答或转人工。
- 未来价格规则必须包含最低毛利、价格上下限、幅度、频率、库存阈值、审批人与停用开关。
- P0 不实现平台 API；业务核心不得直接依赖任一平台字段或 SDK。

## 主要风险与处理

| 风险 | 处理策略 |
| --- | --- |
| 成本不全导致错误毛利 | 缺少任一必需成本时标记“毛利待确认”，不得用于调价建议 |
| 模型编造价格、库存或优惠 | 工具优先、字段来源提示、红队回归、缺失即拒答 |
| 图片主体失真或素材侵权 | 参考图与授权来源校验，导出前人工确认，抽样质检 |
| 需求膨胀到自动经营 | P0 只做事实、建议基础和审批；自动化按路线图逐动作启用 |
| 平台 API 故障波及全局 | 渠道接入中心按 Connector 隔离凭据、队列、限流、重试和告警 |
| Demo 被误认为真实数据 | 所有页面、导出和日志标记 `Demo 数据` |
