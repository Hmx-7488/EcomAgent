# EcomAgent 后续阶段路线图

状态：已确认的规划范围，不构成当前开发需求，2026-07-21  
关联文档：[业务大框架](业务大框架.md)、[项目规划](项目规划.md)、[需求决策台账](需求决策台账.md)

## 使用规则

本文是 P1-P3 功能的唯一规划入口，用于防止后续能力混入 P0。每个阶段获准启动后，必须在对应系统目录中创建正式的 PRD、实现文档、架构文档和验收文档；未创建正式文档包的功能不得开发或验收。

## P1：经营辅助与人工决策

目标：基于 CSV/Excel、授权导出或人工维护的数据，让商家看懂“做什么、赚不赚钱、怎么推广、哪里异常”，但不直接写入任何平台。

| 工作台 | P1 功能 | 数据前提 | 明确边界 |
| --- | --- | --- | --- |
| 选品中心 | 类目/价格带/竞争度/销量/评价/利润空间的机会评分、依据和风险 | 具备来源、时间和口径的样例数据 | 不承诺爆品，不自动立项或采购 |
| 利润中心 | SKU 预估与实际毛利、成本缺失提醒、价格底线 | 成本、价格、订单和费用的可追溯输入 | 不自动改价，不替代财务记账 |
| 推广中心 | 推广素材包、素材版本、人工导入效果数据后的复盘 | 素材、推广花费、曝光/点击/转化等数据 | 不自动投放或购买流量 |
| 运营中心 | 商品、库存、利润、订单、素材和客服异常看板；调价建议 | 标准经营事实与阈值规则 | 不承诺排名，不执行平台动作 |
| 客服中心 | 订单/物流/售后事实导入后的辅助答复与工单建议 | 经授权且最小化的订单事实 | 不自动退款、补发或改地址 |

P1 启动前必须建立 `PRD_P1.md`、`实现文档_P1.md`、`架构文档_P1.md` 和 `验收文档_P1.md`。P1 验收重点是数据口径、建议可解释性、人工审批和异常处理，而不是 AI 的“自主性”。

## P2：渠道只读接入

目标：启用渠道接入中心，以首家合法授权商家的实际经营平台为对象，只读同步业务核心所需的标准事实。

- 授权、Token、平台字段、限流、回调、队列、重试和死信只属于渠道接入中心。
- 首个 Connector 按商品/SKU，再订单、物流、售后和经营数据的顺序实施。
- 同步数据必须携带渠道、外部 ID、来源时间、同步时间、映射版本和新鲜度。
- 业务核心仍只生成经营建议和待审批请求，不直接调用平台 API。

P2 不包含商品发布、平台推广、调价、退款、补发或平台客服消息自动发送。

## P3：受控平台执行

目标：在已经验证的单 Connector 上，逐项开放低风险平台写操作。每项动作独立设计、独立授权、独立验收并具备即时停用能力。

| 候选动作 | 前置规则 | 默认模式 |
| --- | --- | --- |
| 草稿发布/素材推送 | 已审批内容与素材、平台允许、幂等键、可撤回或人工兜底 | 人工确认后执行 |
| 推广计划推送 | 已确认预算、素材和平台权限、预算上限 | 人工确认后执行 |
| 调价执行 | 最低毛利、价格上下限、最大幅度、最大频率、库存阈值、审批人与停用开关 | 先人工确认，再小范围规则化 |
| 客服辅助发送 | 平台官方权限、风险分级、审核与审计 | 默认人工审核 |

自动调价不以“排名第一”为目标或验收承诺。它只能在商家设定的利润和风险边界内执行，且必须可暂停、回滚和追溯。
